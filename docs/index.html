Can an AI agent buy from your store?

More people now ask an AI to shop for them. If a popup, a button or a banner that disagrees with the cart stops it, you lose the sale and never see an error. Cartwalk sends a Kane CLI shopper through your store to find out, lets a coding agent fix what it finds, and keeps a log nobody can quietly edit.

/how-it-works

Walk, judge, fix, prove

An AI proposes, plain code decides, and every step is written to a log that cannot be edited without it showing.

01 · walk

Kane shops your store

In real Chrome, in plain English, with no selectors: read the shipping banner, pick the most expensive product, add one, open the cart, click Checkout. It never pays and types nothing into checkout.

02 · judge

Plain code decides

Kane reports what it saw. Arithmetic and comparisons give each of four checks a pass or a fail. No model's opinion is involved, and a missing value is "unknown", never a quiet pass.

03 · fix

A coding agent repairs it

Failed checks and Kane's evidence go to Claude Code, which can only read and edit your store's folder. Its diff goes in the log.

04 · prove

Kane walks again

A fix only counts if the next walk passes. Every walk, verdict and diff is hash-chained: edit or delete one in the middle and verification names the entry.

the whole instruction Kane receives · lib/shopper.js

You are a shopper who wants to buy one item. If the page shows a free-shipping promise, read it and remember it as shipping_promise, and if it shows none, remember shipping_promise as none and carry on. Choose the most expensive product, select an option if one is required, remember the price the product page shows for that choice as page_price, and add exactly one to the cart. Open the cart. Remember the item price shown in the cart as item_price, the quantity as item_quantity, any discount, coupon or promotion line as discount_line (or none), the subtotal as cart_subtotal and the shipping line as shipping_line. Click Checkout. Look at the page it leads to and remember checkout_stage as payment if it asks for card or payment details, contact if it asks for contact, address or shipping details first, or other if it is neither. Do not type into any field on the checkout pages and never pay.

  /the-deciding-code
  
What the code decides

  
These four checks live in lib/rules.js, with unit tests. A value Kane did not report is "unknown", and unknown never counts as a pass.

  
CheckThe questionHow it is decided

  
reached_checkoutDid the shopper get from the product page to checkout?Passes when Kane finishes and reports the payment page, or a contact-details step first (Cartwalk fills in no personal details, so it says payment was not probed). Fails, with Kane's evidence, only when Kane confirms a product bug such as a failed add to cart, or when Checkout leads somewhere else. If Kane cannot follow the instruction (for example the store has no banner to read) the result is unknown, never a store failure.
step_budgetDid it take a sane number of steps?Counts the clicks, typing and page loads Kane performed. Fails over the budget (20 by default, --budget to change).
price_mathDoes the cart add up?Item price x quantity, minus any discount line, must equal the subtotal. Fails only when the store charges more than that. A discount that does not reconcile, a lower subtotal, an unreported quantity or a product-page price that differs from the cart line is unknown and goes to a human, not to the agent.
shipping_promiseDoes the store keep its free-shipping promise?Reads the threshold from the banner ("over $50"). If the subtotal is at or over it, shipping must be free. Not triggered below it; unknown if no threshold can be read.

  /limits
  
What it does not do

  
    
    
  • It has been run on two third-party public demos, once each: Saleor passed, and on Medusa's demo Kane confirmed a 500 on add to cart (that may be the demo's backend, not Medusa's code). Two walks are not a benchmark.
    • 
    
  • Many real stores ask for contact details before payment. Cartwalk types nothing into checkout, so it says checkout was reached and that payment was not probed.
    • 
    
  • It tests one flow: the most expensive product, one unit, to checkout. No coupons, logins or real payment.
    • 
    
  • The coding agent has no shell, so it cannot run your store. Kane's next walk is the only proof a fix worked.
    • 
    
  • Kane's speed varies: walks took 2.5 to 4.5 minutes, and one test run ended inconclusive when Kane's service was slow. The recorded logs are the fallback.
    • 
    
  • The log catches edits and deletions in the middle. It cannot see entries cut off the end; publish the head hash elsewhere to cover that.
    •
